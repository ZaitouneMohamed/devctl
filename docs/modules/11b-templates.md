# Module 11b — Project templates

Status: built and tested · 2026-11-05

A template is a folder `templates/projects/<id>/` with:
- `template.conf`: `name`, `kind` (laravel | static | proxy | none), `description`,
  `db_engines` (empty = no database), `default_db_engine`;
- `create.sh` defining `tpl_create PATH NAME ENGINE`, optional
  `tpl_configure PATH NAME ENGINE DB_PORT DB USER PASS` (wire the database in), optional
  `tpl_dev PATH NAME PORT` (what `devctl site dev` runs); optional `files/`.
Adding a project type = adding a folder; devctl handles database, ports, web server, SELinux,
ACLs, local name and registry by `kind`.

| Template | Kind | Created with | Served | Database | `site dev` |
|---|---|---|---|---|---|
| laravel-inertia-react | laravel | Composer (official starter kit, dev-main) | PHP-FPM + Caddy, HTTPS | MySQL, PostgreSQL, MariaDB, SQLite | Vite, live reload over HTTPS |
| spring-boot | proxy | start.spring.io: Maven, Java 25, Boot 4.1.2, web + validation + devtools (+ JPA and driver with a database) | Caddy → app on 127.0.0.1:81xx | none, MySQL, PostgreSQL (settings in `devctl.env`, 0600, git-ignored) | `./mvnw spring-boot:run` with the project's JDK |
| laravel-blade | laravel | Composer `laravel/laravel` ^13 | PHP-FPM + Caddy, HTTPS | MySQL, PostgreSQL, MariaDB, SQLite | Vite, live reload over HTTPS |
| laravel-api | laravel | Composer `laravel/laravel` ^13 + `install:api` (routes/api.php, Sanctum) | PHP-FPM + Caddy, HTTPS | MySQL, PostgreSQL, MariaDB, SQLite | — (no front end) |
| static | static | `files/` copied | Caddy serves the folder | — | (edit and reload) |
| java | none | `src/Main.java`, `.java-version` | no website | — | compile `src/` and run `Main` |

Kinds: `proxy` sites get an app port from 8100–8199 (kept forever) and no file access for
Caddy (it only forwards); `none` has no domain, web config or labels. `.java-version` is
validated and maps to `/usr/lib/jvm/java-<v>-openjdk`. Spring's `devctl.env` is read line by
line; only `KEY=value` lines with safe characters are passed to the app (never sourced).

Verified for real on this laptop: static files; Java compiled and run with JDK 25
("Hello from algo on Java 25"); a Spring Boot project generated by start.spring.io (Boot 4.1.2,
Java 25, MySQL). Bug found: `javac` does not accept `--` (fixed).

Dashboard: the New site form has a Template choice and only offers that template's databases.
Tests: `tests/unit/templates.bats` (10) + 1 dashboard test.

## Laravel variants (added 2026-11-05)
All three Laravel templates share `templates/projects/_laravel/laravel.sh` (no template.conf, so
not listed); each sets the package, version and whether it has a front end. The API template
(`vite = no`) runs `install:api`, then — verified on Laravel 13.11 / Sanctum 4.3 — publishes
Sanctum's `personal_access_tokens` migration (install:api does not) and adds the
`HasApiTokens` trait to `app/Models/User.php` (or tells you if the file looks different).
Verified for real: an API project created with SQLite issued a Sanctum token.
